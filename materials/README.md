# Material provenance

[provenance.json](provenance.json) owns the bounded fixture and extracted-string
inventory: current byte identities, reported sources, measured format metadata
and unresolved questions. The checked subset is FLAC/M4A under `fixtures/`,
text outputs under `evidence/native-scan/`, and the named Cast key/skin records.
It is a provenance record, **not a publication
allowlist, a secret-scanner exclusion or a legal-clearance certificate**.

## What each kind of evidence means

A Git addition establishes repository custody, not who generated the original
PCM, whether a recording is synthetic, or the rights to distribute it. Generic
test tags and a short duration are supporting context, not proof of origin.
The documented sine-generation recipe is owned by the source-format test
referenced in the registry. Its recorded byte-identical regeneration supports
that specific fixture and tool version, not every audio file in the folder.
The three ALAC fixtures are regenerated by `recipes/alac-fixtures.sh` from
lavfi signal only (with a fixed-seed noise floor for real 24-bit precision);
the registry binds the script digest, the ffmpeg version and each output hash,
and records the replaced bytes as `previous_sha256`. The cover embedded in
`44k-16bit-art.m4a` is generated by that recipe; the standalone supporting
`fixtures/cover.png` remains a separate item without generation documentation.
The FLAC fixtures are not covered by that recipe and remain explicitly
unresolved.

Measure format from the file, never from its name. The legacy
`176k-24bit.flac` name misstates its stored depth; the registry records the
STREAMINFO result without renaming or rewriting the media. Encoded depth,
decoder sample storage and physical output are separate concepts. Lossy AAC
has no lossless source bit-depth claim here. Byte-identical aliases are listed
as aliases, not independent evidence of authorship.

Extracted-string filenames do not make their contents working endpoints.
The retained outputs include domain suffixes, certificate URLs with extraction
noise, JNI/C++ symbols, diagnostics and SQL fragments. None was sent as a
request in this review. An empty extraction output says nothing about the
absence of an API in the source library. Historical reports identify an APK
and a method, but this pass did not reacquire that APK or reproduce extraction.
Those reports' old capability and legal conclusions are not current verdicts.
Factual names and copied expressive material can require different analysis;
neither the app license nor a proprietary source label decides every case.

The Cast key fixture and skin match blobs in the pinned Spotifast source tree.
The enclosing MIT grant and retained copyright notice matter; lack of a notice
inside a skin archive alone is not evidence that it is unlicensed. Conversely,
blob identity does not prove all embedded component rights. The key's test
certificate context supports upstream fixture provenance, not production
nonuse, trusted certificate chains or permission to authenticate. Do not print
private key material, sign with it, rotate it automatically, or suppress all
private-key findings because this fixture is documented.

## Maintaining the record

Keep material changes separate from decisions about distribution. Record a
known source or reproducible generation method when available; keep an explicit
unresolved question when it is not. Do not turn an unknown into a verified
claim by changing a status label. Preserve original copyright and license
notices. A new source, regenerated fixture or deliberate exclusion needs its
own review, not an unrecorded deletion of a difficult item.

The CI test `ci/test_material_provenance.py` checks coverage of this declared
subset, local artifact identities, supporting-file bindings, FLAC header
metadata and that every ALAC record still binds to the recorded recipe script
and its regenerated hashes. Its negative cases reject missing inventory entries, tampered bytes
and filename-derived depth guesses. It does not establish third-party grants,
validate remote sources, or run authentication, playback or DRM software.
Git history and executable-release permissions remain separate decisions.
