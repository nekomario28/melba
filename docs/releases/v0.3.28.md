# Melba v0.3.28 — a paused player stops holding the card

Melba v0.3.28 is a patch release on the same **glibc 2.35** baseline.

## A paused daemon no longer reserves the output device

`melbad serve --paused` used to open the exclusive PCM and pause it, so the card
stayed reserved for as long as the window was open. It now holds the *selection*
and opens the device when a command actually plays.

Measured on this host's USB DAC, which no other process was using:

| build | after a paused queue load | after `Play` |
| --- | --- | --- |
| v0.3.27 | `fuser` lists the daemon, substream `PREPARED` | — |
| v0.3.28 | no substream exists at all | `RUNNING`, owned by the daemon |

The source is still described while paused — rate, length and the position a
queue load parks all come from the probe, not from the card — so the window shows
what *would* play.

Three faults had to be fixed for this to be honest rather than merely quiet, and
each was found by a failing test: `Previous` onto a source that cannot be opened
walked forwards again and replayed the track you just left; `mpris:trackid` moved
only when something played, so a cursor move while paused was invisible to media
controllers; and re-loading an identical queue reset the play history, which is
what a frontend re-sync does on every change it hears about.
`evidence/paused-device-release.md` records the measurement and what it does not
establish.

## `hi-res` asks for a specific ALAC rendition

`melbad config audio-quality hi-res` (Settings → Stream quality → *Hi-res
lossless*) asks for the highest-bitrate ALAC rendition the master lists, chosen
from each variant's `BANDWIDTH`/`AVERAGE-BANDWIDTH`. A variant that states no
bitrate is a last resort rather than a winner, a non-ALAC variant is never picked,
and a master without ALAC still falls back to AAC.

**Not verified against the service.** No live account's master has been read, so
this documents the setting, not "this plays the hi-res rendition". The receipt
keeps reporting the rate and depth that actually arrived, so a fallback shows up
as AAC.

## Going back a release

`install-release.sh` accepts a tag:

```sh
sh packaging/install-release.sh --version v0.3.27
```

It fetches that release's signed manifest, verifies it with the same pinned
publisher key, checks the archive and installs it. An unversioned tag is refused
before any URL is built, and a tag that does not exist fails before anything is
written.

## Smaller things

- **The wrapper log is capped** at 16 MiB per session. It used to grow for as
  long as the session lasted — one machine logged 14 GB in a night — so a wrapper
  looping on an error could fill the disk with the window idle.
- **HTTP connections are reused.** Each request used to build its own agent, and
  `ureq` pools per agent, so every request paid a fresh TCP + TLS handshake;
  segment range fetches during playback made that the most frequent case.
- **`ureq` 3.** The credentialed path still refuses redirects and resolves the
  target itself; because `ureq` 3 parses URLs with the `http` crate, which keeps
  `..` verbatim, the redirect join now normalises the path *before* the allowlist
  check sees it.
- **The release toolchain is pinned** (`rust-toolchain.toml`, 1.99.0, and every
  workflow step), so rebuilding this tag later produces the same binaries.
