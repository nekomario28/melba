# Melba v0.4.0: responsive playback controls and clearer settings

Melba v0.4.0 brings direct queue selection, responsive Next/Previous during loading, and a settings layout that adapts to the window. It retains the Linux portable package format and established publisher signing key.

## New

- **Select a song in Next up directly.** One command selects the requested queue occurrence without opening intervening songs. The original context, remaining shuffle plan and visited history are preserved, including duplicate songs.
- **Settings that fit the window.** A bounded, centered content column uses wider windows without unbounded text lines. Complex controls move below readable descriptions when necessary; narrow quality choices stay grouped and ordered. Output selection and refresh no longer share an undersized slot, and long selected values have full-value tooltips. Small switches remain beside their labels.

## Fixed

- **Next and Previous supersede obsolete loading.** Both directions share cancellation and navigation, including mixed bursts. Established source HTTP connections, wrapper TCP reads and pipe readers can be interrupted without waiting for the old response or creating a loader thread per press.
- **Late work cannot undo a selection.** Manual navigation invalidates older GUI context resolution. Cancelled work is not treated as a failed track or a reason to try a preview; cancelled preview downloads do not leave partial cache entries. Speculative segment workers have a process-wide bound.
- **Previous keeps its playback rule and actual history.** A visited song beyond three seconds restarts first; subsequent presses go backward. Unfinished loading candidates do not inherit the old position or count as visited merely because their URI matches another occurrence.
- **Desktop media controls learn when skipping becomes available.** MPRIS `CanGoNext` and `CanGoPrevious` now emit property changes when queue navigation capabilities change, so controllers such as KDE Plasma do not retain a stale disabled state after an empty queue.
- **Play works after reaching or clearing the end of a queue.** Stopped queues no longer publish stale track metadata, and the GUI no longer submits empty track URIs. Demo and headless backends are isolated from the normal session daemon.

## Dependency maintenance

The lockfile updates `quinn-udp` to 0.5.16 for [RUSTSEC-2026-0538](https://rustsec.org/advisories/RUSTSEC-2026-0538). This was a release-blocking dependency-audit finding, not an observed Melba playback failure: HTTP/3 is not enabled in Melba's dependency graph, and the advisory identifies Linux's receive path as unaffected. Existing audit warnings retain their existing classification; no advisory is suppressed to pass this release.

## Updating

Update **both `melba` and `melbad`**, then fully quit and relaunch Melba so its playback daemon restarts too. The direct-selection command requires the matching daemon. Existing settings and queue files retain their format; this release introduces no data-format migration. Standard installations remain on stable updates; the developer-only `"update_channel": "alpha"` opt-in also accepts this stable release after the 0.4.0 alphas.

## Verification

Regression coverage includes blocked-source cancellation before the old source is released, actual stalled HTTP header/body sockets, queue history, mixed directions and responsive widget geometry. The maintainer accepted the installed playback/navigation and settings builds and reported stable playback on alpha.2. Release automation checks the source, both GNU ABI builds and the candidate archives before signing and publication, then verifies the published signature, archives and installer.

Fresh sign-in, real-session expiry recovery and GUI sign-out/re-login were **not re-tested for 0.4.0**. The authentication core, GUI sign-in orchestration, session-restore and sign-out bodies are unchanged from v0.3.30. Shared HTTP cancellation and test-backend isolation did change; their normal authentication paths were reviewed, not re-certified with a live account. The maintainer accepted this verification scope. Full catalog AAC playback beyond 30 seconds was not separately re-measured for this release; the playback acceptance above is not a new codec-specific measurement.

## Limits

Linux is the runtime-tested platform. Cross-platform compile checks and ARM64 builds do not establish physical audio acceptance on those systems. Cancellation is not an unconditional deadline for native DNS/connect establishment, regular-file kernel stalls or native CDM calls. Audio-path limitations and the external, user-supplied ALAC service requirement remain unchanged. EQ, crossfade, normalization and Atmos are not added by this release.
