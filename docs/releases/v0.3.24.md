# Melba v0.3.24 — the last unanswered command, and a cover you can choose

Melba v0.3.24 is a patch release on the same **glibc 2.35** baseline. It removes a
surface that never worked, finishes the two playlist-cover commands, and makes
the project's own gate script stop writing into a real state directory.

## The radio is gone

Apple publishes no station endpoint. `Command::Radio` was sent by the app and
answered by nothing, so a station page never listed its songs — the last entry in
the recorded-exception list. It was a Spotify concept, like the podcast surface
already removed, so it is gone end to end: the page, the daemon command and its
event, the "Go to… radio" menu entries, the view, the station URI helpers, the
fixtures and the tests that only exercised them.

`ci/test_daemon_commands.py` now records an **empty** exception set: a command the
app sends and nothing answers fails the gate instead of joining a list.

## Choosing a playlist cover works

Two commands the app sent were dropped by the worker's catch-all: a chosen cover
was never compared with the service's renditions, and the native picker's future
went nowhere. `CheckPlaylistCover` now fetches each candidate and compares pixels
(no upload involved), and `ChoosePlaylistCover` awaits the picker and prepares the
file through the same JPEG/PNG and size limits as before.

## Fixes found while working on it

- **`ci/check.sh` wrote into the live state directory.** It starts a real daemon
  for its MPRIS gates and gave it no XDG directories, so the daemon replaced the
  live queue with the fixtures it was handed. Every subprocess the script starts
  now resolves into one throwaway root — measured with a canary in `queue.json`.
- **`published signed installer (fedora-43)` failed twice on its mirror.** It now
  retries, and when the mirror is the reason it emits a warning saying the
  release was not verified there, instead of failing a published release.

## Compatibility evidence

Same as v0.3.13 through v0.3.23: the published archives need at most
`GLIBC_2.35` (`melba`) and `GLIBC_2.34` (`melbad`), the workflow executes the
candidates in Debian 12/13, Ubuntu 22.04/24.04/26.04, Fedora 43/44 and Arch
containers, and it installs the signed release with `install-release.sh` in
five of them.

This is launch and shared-library compatibility only — not Apple sign-in,
desktop rendering, physical audio output or ALAC playback, and not a
run-verification of ARM64 on target hardware.

## Still required on the user's machine

Unchanged: AAC-256 needs a Widevine CDM already installed by Chrome, Chromium or
Vivaldi, and ALAC needs a FairPlay decrypt service the user supplies.
`melbad doctor` reports both.
