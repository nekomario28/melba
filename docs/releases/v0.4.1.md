# Melba v0.4.1: URL schemes registered on release installs

Melba v0.4.1 fixes the signed-release installer so it registers Melba's Apple
Music URL schemes, and takes the current round of routine dependency updates.
It keeps the **glibc 2.35** baseline and the paired, publisher-signed
`melba` / `melbad` portable packages for x86_64 and aarch64.

## Fixed

- **Release installs now register the URL schemes.** The signed-release
  installer used to write the desktop entry from a hand-copied template that
  had lost its `MimeType=` line, so `itms://`, `itmss://`, `music://`,
  `musics://` and `apple-music://` links never reached a release-installed
  Melba even though the app handles `melba <link>`. Signed archives now carry
  the canonical `melba.desktop` and the installer derives the installed entry
  from it, rewriting only the machine-specific `Exec`/`Icon` lines. The
  signing job refuses an archive that lacks the file, and a drift guard keeps
  the old-archive fallback in lockstep with the canonical entry (#150).
- Registering the schemes makes Melba a *candidate* handler; as before, the
  installer does not change which application the desktop uses by default.

## Dependency maintenance

Routine updates only, no behaviour change intended: `ureq` 3.5.2, `rand`
0.10.2, `nix` 0.31.3, `jsonschema` 0.61.2 (with pinned notices for
`jsonschema-regex`/`jsonschema-value`), `plist` 1.10.3, `sha2` 0.11.1, `libc`
0.2.191, `jiff` 0.2.43, `crc32fast` 1.5.5, `winresource` 0.1.34, and the CI
`install-nix-action` pin. Contributor-facing documentation and the desktop
toolchain pins were aligned with the signed-release flow (#138).

## Updating

Update **both `melba` and `melbad`** — the paired installer already does this —
then fully quit and relaunch Melba. Existing installs pick up the missing
scheme registration from the new archive's desktop entry; installing this
release is enough, no manual `xdg-mime` step is required.

## Verification

The installer change was covered by new regression tests observed failing
against the unfixed script, then passing; the full local suite ran in an
isolated HOME/XDG/D-Bus environment. The maintainer verified the fixed path on
the real installation before merge: a signed-release install registers the
schemes and an `itms://` link reaches Melba. Release automation checks the
source, both GNU ABI builds and the candidate archives before signing and
publication, then verifies the published signature, archives and installer in
five distro containers.

Fresh sign-in, real-session expiry recovery, GUI sign-out/re-login and
full-length account playback were **not re-tested for 0.4.1**; the
authentication and playback bodies are unchanged from v0.4.0. That acceptance
scope remains open in the [roadmap](../roadmap.md).

## Limits

Linux is the runtime-tested platform. ARM64 is build-verified, not verified on
physical ARM64 audio hardware. No codec, output-path or account-playback
measurements are claimed by this release.
