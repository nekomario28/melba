# Melba v0.3.25 — the header agrees with the row

Melba v0.3.25 is a patch release on the same **glibc 2.35** baseline. It fixes a
cover that one screen drew and the next did not.

## A playlist's page header kept a placeholder

v0.3.24 introduced one answer for a playlist's cover — the service's picture, or
a group icon composed from its first tracks — and every renderer asked it. The
page header did not, because the decision was made at each call site and only
the *loading* header had been given it: once the playlist loaded, the header was
drawn with no group art while the sidebar row beside it showed one.

It is decided in one place now, inside the function that builds a playlist
header, so a new header path cannot forget it. `HeroImages` owns the covers
rather than borrowing them, because they are read from the app while the header
draws.

Two guards hold the shape: the decision itself (asked once, nothing until the
answer, the service's picture wins) and a source-level check that the fill stays
inside the header function and appears only there.

## Compatibility evidence

Same as v0.3.13 through v0.3.24: the published archives need at most
`GLIBC_2.35` (`melba`) and `GLIBC_2.34` (`melbad`), the workflow executes the
candidates in Debian 12/13, Ubuntu 22.04/24.04/26.04, Fedora 43/44 and Arch
containers, and it installs the signed release with `install-release.sh` in
five of them.

This is launch and shared-library compatibility only — not Apple sign-in,
desktop rendering, physical audio output or ALAC playback, and not a
run-verification of ARM64 on target hardware.

## Still required on the user's machine

Unchanged: AAC-256 needs a Widevine CDM already installed by Chrome, Chromium or
Vivaldi, and ALAC needs a FairPlay decrypt service the user supplies.
`melbad doctor` reports both.
