# Melba v0.3.29 — the rendition you asked for

Melba v0.3.29 is a patch release on the same **glibc 2.35** baseline.

## `lossless` stops asking for hi-res, `auto` keeps it

v0.3.28 chose "the first ALAC variant the master lists". Read against a real
master, that rule is wrong: Apple lists the **hi-res** rendition first.

Measured on "So What" (Kind of Blue, `268443097`), the two ALAC variants are

| rendition | bandwidth | rate | depth |
| --- | --- | --- | --- |
| `gr2304_alac` | 1,761,161 | 48,000 | 24 |
| `gr9216_alac` | 4,995,600 | 192,000 | 24 |

so v0.3.28 asked for 24-bit/192 kHz under the *lossless* setting. The rendition is
now chosen by the declared bitrate, matching Apple's own two tiers: `lossless`
asks for the base tier (24/48 here) and `hi-res` for the highest (24/192).

`auto` **keeps asking for the best the release offers**, which is what v0.3.28 did
in practice — otherwise everyone who never opened Settings would have been moved
from 24/192 to 24/48 without asking.

Not every master serves two renditions: one album advertising `hi-res-lossless`
and one advertising only `lossless` each served a single ALAC variant, where the
setting changes nothing. The choice reads each master's numbers instead of
assuming a shape. `evidence/hires-variant-selection.md` records all of it,
including that no audio was decoded — the decrypt service was not started, so what
is verified is which playlist is requested.

## The setting is in the settings screen, and it looks right

Settings → Stream quality offers 自動 / AAC 256 / ロスレス / ハイレゾロスレス. Capturing
that screen showed the row was wrong twice: the description ran underneath the four
pills (the row reserved less width than they need), and the whole row was still
English inside Japanese settings. The row now measures the pills it offers, the
copy says what `auto` does, and the strings are translated.
`evidence/ui-stream-quality-ja.png` is the captured frame.
