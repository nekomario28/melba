# Melba v0.3.30: 24-bit output and reliable Pause/Resume

Melba v0.3.30 fixes PCM-format negotiation and playback-position recovery on
Linux. It keeps the **glibc 2.35** baseline and the paired, publisher-signed
`melba` / `melbad` portable packages for x86_64 and aarch64.

## Fixed

- **24-bit playback on cards that only accept packed samples.** `S24_3LE` is
  offered alongside the wider containers, and both playback writers handle its
  three-byte layout. The two ALSA/Rust format spellings are recognised. A USB
  device that previously refused 24-bit playback was measured running at 48 kHz
  with this format, advancing position and no XRUNs (#128).
- **Correct S24_LE output.** Its 24 significant bits are placed in the low three
  bytes of a four-byte container, rather than confusing it with S24_3LE. FloatLE
  is no longer offered for an integer stream that the writer cannot preserve
  exactly (#130).
- **A more honest bit-perfect verdict.** Hardware precision comes from the
  committed ALSA setup, not the container width. Missing precision is not
  silently treated as sufficient (#130).
- **Pause/Resume on outputs without working native controls.** Software Pause
  saves the selection and position, closes the PCM, and reopens on Play. A
  failed native Resume uses the ring-buffer snapshot captured before the
  failure, so invalidated pointer accounting cannot skip the unplayed tail.
  Unknown buffer accounting stops with an explicit error instead of guessing
  that the tail is empty (#130).
- **Seeks and Stop keep the right cursor.** Seeking while software-paused now
  updates the saved resume position, Stop clears it, and a native-paused seek
  discards the old buffer. Fractional packet durations accumulate without
  rounding each packet down independently (#130).

## Verification

On a Yamaha RX-V6A connected over HDMI, physical ALSA `hw:1,7` accepted stereo
16-bit sources at 44.1/48 kHz and 24-bit sources at 48/96 kHz. The 24-bit sources
used S32LE, which this HDMI device offers. Native Pause/Resume was repeated with
stable paused positions, renewed progression and no XRUNs. The user explicitly
confirmed audible 16-/24-bit playback and at least two clean Pause/Resume cycles.

A separate real-ring probe deliberately failed native Resume with unplayed audio
still buffered. Both cycles reopened near the saved audible cursor and advanced
without XRUNs. Regression tests also cover a 200 ms buffered tail, unavailable
buffer accounting, paused seeks, Stop and fractional frame arithmetic.

The source acceptance and measurements are recorded in
[PR #130](https://github.com/nekomario28/melba/pull/130),
[direct-output evidence](../../evidence/pr130-hardware-20261113.md) and
[Resume-buffer evidence](../../evidence/pr130-resume-buffer-20261113.md).
The release gates check both GNU ABI builds and the actual candidate archives in
eight Linux environments before signing and publication.

## Limits

The physical Resume failure was injected, not a naturally observed driver fault.
Symphonia seeks remain packet-granular rather than sample-exact. These tests do
not measure the receiver's analog output or downstream DSP, and do not certify
every audio device, codec, live output switch or account playback path. ARM64 is
build-verified, not verified on physical ARM64 audio hardware.
