# Melba v0.3.30 — 24-bit audio on the DAC that only takes S24_3LE

Melba v0.3.30 is a patch release on the same **glibc 2.35** baseline.

## 24-bit playback where only the packed format is offered

A USB DAC here offers exactly `S16_LE, S24_3LE` at 48 kHz and rejects the two wider
24-bit containers, so 24-bit audio could not be played on it at all:

```
open: Rejected { device: "hw:0,2", why: "no format carries 24bit @ 48000Hz x2ch" }
```

The message was accurate about the attempt and wrong about the cause — `aplay`
plays a packed 24-bit WAV on the same device without complaint. Linux has three
24-bit formats and a card may offer only one of them; the candidate list held two.

`S24_3LE` is now a candidate, and both writers have a packed branch: three bytes per
sample from the source's top 24 bits, a frame being 3 × channels bytes. Measured on
that device with `lossless`:

```
/proc/asound/card0/pcm2p/sub0/hw_params
format: S24_3LE   channels: 2   rate: 48000 (48000/1)

pos_ms: 2040 → 4080 → 6035 → 8075 → 10115 → 12070
verdict: BITPERFECT   xruns: 0
```

Two traps are worth naming, because each cost a wrong conclusion first:
`Granted::format` is built with `{:?}`, which prints the Rust variant name `S243LE`
while ALSA prints `S24_3LE` — a branch matching only the latter never ran, and the
stream fell through to the i32 writer, which answered `io_xx: Operation not
supported`. And the first packing test had wrong expected bytes for negative
samples; the test caught it before the device did.

`evidence/dac-24bit-format-negotiation.md` records the measurement, the `aplay`
evidence and what is still unmeasured: one device, and no analogue or listening
test.

## Verification

Workspace 162 pass (including new unit tests for the candidate list, the packed
bytes and the two spellings of the format name), `ci` 107 OK (skipped=3),
`cargo fmt --check`, `clippy -D warnings`, and the release pipeline's GNU-ABI
baseline for both architectures.
