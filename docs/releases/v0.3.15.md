# Melba v0.3.15 — Liked Songs actually opens the Favorites playlist

Melba v0.3.15 is a patch release on the same **glibc 2.35** baseline. It fixes
one thing v0.3.14 claimed and did not deliver.

## Fix

**In v0.3.14, Liked Songs still showed the library list.** The page asked the
daemon which library playlist was the account's Favorites list, then guarded the
answer with the shared page-load counter. Opening Liked Songs moves that counter
on the way in — the page load turns into the liked-songs cache load, which
increments it — so the answer never matched and was dropped. The page stayed on
the library-backed stand-in for the whole session.

The lookup now carries its own counter, which nothing else touches, and a
regression test covers an unrelated load that moves the shared counter while the
lookup is in flight. Putting the shared counter back makes that test report
`left: LikedSongs`, so the guard fails when the defect returns.

Nothing else changed: the filled heart for a song loved without a library copy
already worked in v0.3.14, because that reads the account's rating on a
different path.

## Compatibility evidence

Same as v0.3.13 and v0.3.14: the published archives need at most `GLIBC_2.35`
(`melba`) and `GLIBC_2.34` (`melbad`), the workflow executes the candidates in
Debian 12/13, Ubuntu 22.04/24.04/26.04, Fedora 43/44 and Arch containers, and it
installs the signed release with `install-release.sh` in five of them.

This is launch and shared-library compatibility only — not Apple sign-in,
desktop rendering, physical audio output or ALAC playback, and not a
run-verification of ARM64 on target hardware.

## Still required on the user's machine

Unchanged: AAC-256 needs a Widevine CDM already installed by Chrome, Chromium or
Vivaldi, and ALAC needs a FairPlay decrypt service the user supplies.
`melbad doctor` reports both.
