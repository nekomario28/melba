# Melba v0.3.21 — a playlist that looks like its songs

Melba v0.3.21 is a patch release on the same **glibc 2.35** baseline. Two things
a screenshot caught, both about a playlist: what its tile shows, and whether the
same songs are offered twice.

## The group icon is made of the playlist's songs

A user-made playlist has no artwork of the service's own, and Melba filled the
gap with a cover derived from the playlist's **name**. The service composes a
**group icon from the first tracks** instead, and that is what the tile shows
now: four squares, halves when there are two or three, a single cover for one.

The client asks for exactly that — a new `PlaylistMosaic` request returns the
artwork of the playlist's first four tracks, deduplicated — once per playlist per
session and only for the listed playlists that have no artwork. The name-derived
cover stays as the fallback for the moment before the answer arrives, and the
library grid uses the same group icon.

## Liked Songs stops appearing twice

Home showed a synthetic Liked Songs tile next to the account's own Favorites
playlist. A guard was meant to drop the synthetic one once the real playlist was
known, but the lookup that identifies it was only requested when Liked Songs was
**opened** — so anyone who never opened it kept both. The lookup now runs when the
library playlists load, which is the moment the tile is drawn.

The tile still has a purpose: accounts without such a playlist keep it, because
it is then the only way in.

## Compatibility evidence

Same as v0.3.13 through v0.3.20: the published archives need at most
`GLIBC_2.35` (`melba`) and `GLIBC_2.34` (`melbad`), the workflow executes the
candidates in Debian 12/13, Ubuntu 22.04/24.04/26.04, Fedora 43/44 and Arch
containers, and it installs the signed release with `install-release.sh` in
five of them.

This is launch and shared-library compatibility only — not Apple sign-in,
desktop rendering, physical audio output or ALAC playback, and not a
run-verification of ARM64 on target hardware.

## Still required on the user's machine

Unchanged: AAC-256 needs a Widevine CDM already installed by Chrome, Chromium or
Vivaldi, and ALAC needs a FairPlay decrypt service the user supplies.
`melbad doctor` reports both.
