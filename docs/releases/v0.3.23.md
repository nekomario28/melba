# Melba v0.3.23 — one answer for a playlist cover

Melba v0.3.23 is a patch release on the same **glibc 2.35** baseline. It finishes
what v0.3.21 started: the group icon now appears on every surface, not on two.

## The same playlist looked different on different screens

v0.3.21 composed a group icon from a playlist's first tracks for the Home tile
and the library grid. The playlist's own page header still drew a flat
placeholder — not a missing case, a missing owner: each surface decided for
itself.

`PlaylistCover` answers once now — the service's picture when it has one, the
group icon when it does not — and the page header, the Home tiles and cards, the
library grid and rows, and the search top result all ask it. Any of them can also
request the group icon when it has neither, so a playlist opened from a link no
longer leaves its header empty while the rows beside it show a picture.

The drawing matches one icon rather than four pictures: cells meet without a gap,
and only the cells on the tile's edge carry the rounding, so the corners of the
group follow the tile.

## Compatibility evidence

Same as v0.3.13 through v0.3.22: the published archives need at most
`GLIBC_2.35` (`melba`) and `GLIBC_2.34` (`melbad`), the workflow executes the
candidates in Debian 12/13, Ubuntu 22.04/24.04/26.04, Fedora 43/44 and Arch
containers, and it installs the signed release with `install-release.sh` in
five of them.

This is launch and shared-library compatibility only — not Apple sign-in,
desktop rendering, physical audio output or ALAC playback, and not a
run-verification of ARM64 on target hardware.

## Still required on the user's machine

Unchanged: AAC-256 needs a Widevine CDM already installed by Chrome, Chromium or
Vivaldi, and ALAC needs a FairPlay decrypt service the user supplies.
`melbad doctor` reports both.
