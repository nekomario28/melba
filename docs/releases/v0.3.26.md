# Melba v0.3.26 — choose the stream, and stop a test helper from lying

Melba v0.3.26 is a patch release on the same **glibc 2.35** baseline.

## The stream is a preference, not a rule

`melbad` decided on its own: lossless when a decrypt service was configured and
the track carried a lossless variant, AAC-256 otherwise. That is a fine default
and a poor only-option — someone who does not run the service, or who wants the
verdict to stop depending on one, had no way to say so.

`config.json` now carries `audio_quality`, set from the command line or from
**Settings → Stream quality**:

```sh
melbad config audio-quality            # what is in effect
melbad config audio-quality aac        # never ask the decrypt service
melbad config audio-quality lossless   # ask for lossless, fall back if it cannot
melbad config audio-quality auto       # the default rule
```

`aac` is honoured literally: the service is not started at all. A fallback from
`lossless` reports an `alac_fallback` diagnostic with the reason and the wanted
quality, and the receipt's `codec` says what actually played.

There is no `hi-res` value, and the documentation says why: telling a hi-res ALAC
variant from a lossless one needs the master playlist's per-variant attributes,
which `melba-cdm` does not parse, and without an account there is no live master
to check a guess against. A hi-res track plays the ALAC variant the service lists
first, and the receipt reports what arrived.

## A process-lifetime test helper no longer turns a race into a failure

`tests/process_owner.py::alive` read `/proc/<pid>/stat` and treated only
`FileNotFoundError` as "gone". A process that disappears between opening the file
and reading it raises `ProcessLookupError`, which failed the whole `gates` job on
a pull request that only touched a document. Every reason the entry cannot be
read means the same thing there, so the helper takes `OSError`.

## A measured attempt that was reverted, and recorded

Deferring the output open until the first Play works on `hw:1,7` — paused leaves
the PCM `closed` while the metadata still reports `alac`/24-bit — but it broke
three transport tests: Next and Previous while paused depend on an *opened*
occurrence, so the history they consult was empty. The roadmap records the
measurement and that the real fix is how skipped entries are remembered.

## Compatibility evidence

Same as v0.3.13 through v0.3.25: the published archives need at most
`GLIBC_2.35` (`melba`) and `GLIBC_2.34` (`melbad`), the workflow executes the
candidates in Debian 12/13, Ubuntu 22.04/24.04/26.04, Fedora 43/44 and Arch
containers, and it installs the signed release with `install-release.sh` in
five of them.
