# Melba v0.4.0-alpha.2: pre-release for alpha testing

Melba v0.4.0-alpha.2 is a signed pre-release for testing the 0.4.0 changes and the GUI update path ahead of the stable 0.4.0 release. The latest stable release remains **v0.3.30**.

## Fixed

- **MPRIS skip capability updates for desktop media controls.** `melbad` now marks `CanGoNext` and `CanGoPrevious` with `EmitsChangedSignal=true` and emits them in `org.freedesktop.DBus.Properties.PropertiesChanged` whenever queue navigation capabilities change (such as loading, enqueueing, emptying, or toggling loop status). Desktop controllers like KDE Plasma's `mprisservice` no longer stay stuck on a cached `CanGoNext = false` after an empty or exhausted queue startup.
- **Playback after stopping past the end of a queue.** Clears stale track metadata when stopped past queue end and guards empty-URI playback requests cleanly so starting or selecting tracks afterwards works reliably.

## Inherited from v0.4.0-alpha.1

- Direct upcoming-occurrence selection in **Next up** (`MelbaPlayQueued`), cancellable directional Next/Previous loading, responsive Settings layout, and developer-only `"update_channel": "alpha"` opt-in in `settings.json`.

## Updating

Update **both `melba` and `melbad`**, then fully quit and relaunch Melba so its playback daemon restarts too. Existing settings and queue files retain their format; this pre-release introduces no data-format migration.

## Known pre-release status and limits

- **Authentication gates remain open for stable 0.4.0.** Fresh native sign-in / 2FA, expired-session recovery and GUI sign-out have not yet been verified end-to-end on this release candidate.
- Linux is the runtime-tested platform. Cross-platform compile checks and ARM64 builds do not establish physical audio acceptance on those systems. Audio-path limitations and the external, user-supplied ALAC service requirement remain unchanged.
