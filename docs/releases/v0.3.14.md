# Melba v0.3.14 — the heart follows what you actually liked

Melba v0.3.14 is a paired GUI/daemon release built against the same **glibc
2.35** baseline as v0.3.13.

## Changes

- **A liked song now shows a filled heart even when it was never added to the
  library.** Apple stores "liked" and "in the library" as two independent
  signals: a song loved in the Apple Music app lands in the account's Favorites
  list without joining the library, so reading the library flag alone left the
  heart hollow. Melba now reads the account's own rating
  (`/me/ratings/songs`), which is per account rather than per playlist.
  Measured on one account: 84 of the 85 Favorites entries carried a rating,
  while only 11 of 100 library songs did.
- **Liked Songs opens the playlist Apple actually keeps for it.** The page used
  to list `/me/library/songs`, which hid most of what the account liked — 53 of
  84 liked songs on the measured account were never added to the library. The
  Favorites playlist has no id or name that is stable across accounts, so it is
  identified by what it contains: among the read-only library playlists it is
  the one whose songs are all rated (100% for Favorites, 0–16% for the mixes and
  editorial lists in the same account). Accounts where no such playlist exists
  keep the library-backed page.
- Toggling a heart now records or clears the rating too, so the account's
  Favorites list agrees with the heart the app drew. A single heart writes one
  rating; a bulk save stays one library request.
- The bug-report link compiled into every gettext catalog pointed at a
  repository that no longer exists; it now names this one.

## Compatibility evidence

The published archives require at most `GLIBC_2.35` (`melba`) and `GLIBC_2.34`
(`melbad`), measured on the x86_64 candidates. The release workflow executes the
candidates in real Debian 12/13, Ubuntu 22.04/24.04/26.04, Fedora 43/44 and
Arch containers, then installs the signed release with `install-release.sh` in
five of them.

This proves launch and shared-library compatibility in those containers, **not**
Apple sign-in, desktop rendering, physical audio output or ALAC playback. ARM64
is build-verified on a native ARM64 runner, not run-verified on target hardware.

## Still required on the user's machine

Nothing in this release changes what playback needs: AAC-256 needs a Widevine
CDM already installed by Chrome, Chromium or Vivaldi, and ALAC needs a FairPlay
decrypt service the user supplies. `melbad doctor` reports both.
