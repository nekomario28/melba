## Native Pause/Resume

A 45-second 48 kHz/24-bit stereo WAV was served on the physical output.
Kernel `/proc/asound/card1/pcm7p/sub0/status` transitioned RUNNING → PAUSED →
RUNNING in both cycles; hardware pointers were unchanged across each pause.
The same stream remained open (`streamOpens=1`), establishing **native** Pause,
not software fallback. No XRUN was reported.

| Cycle | Playing position | Paused | After 2 seconds paused | After resume |
|---|---:|---:|---:|---:|
| 1 | 2472 ms | 2568 ms | 2568 ms | 4608 ms |
| 2 | 4680 ms | 4752 ms | 4752 ms | 6720 ms |

A seek to 15000 ms reached 16008 ms after about one second. Stop reported
Stopped/0 ms and kernel SETUP (the existing Stop path retains the open handle).
Quit released the PCM. After unsuspending the sink, `paplay` successfully used
that exact PipeWire sink; it returned to IDLE and PipeWire owned the PCM again.
Other sinks were not changed.

## Fallback regressions and repair

The real D-Bus/decoder/player loop is exercised with ALSA null and a small
LD_PRELOAD fixture that rejects Pause or Resume and throttles writes. Trace
assertions require the injected failures to occur, and stream-open counters
require actual reopen, not just a reported Playing state.

Two failures were observed before their repairs:

- Seek while software-paused changed the reported cursor to 15000 ms, but
  Resume returned to 528 ms. The paused-selection loop now updates pending seek.
- Stop while software-paused reset the display but retained the parked cursor;
  Play restarted at 20528 ms. Stop now clears the parked cursor before reporting
  Stopped.

Tests cover two cycles of both rejected Pause and rejected native Resume,
stable paused position, progression after reopen, parked Seek, and Stop→Play.
These are controlled integration tests, **not physical non-native-Pause proof**.

## Remaining acceptance / review boundaries

- **Audibility is unverified:** a person must confirm clean 16-/24-bit playback,
  actual silence on Pause, and clean sound on both Resumes. Logs cannot prove it.
- RX-V6A used native Pause. Physical fallback and buffered-audio continuity on
  a failed native Resume remain unverified. In the paused hardware snapshots,
  kernel `delay` was zero despite different application/hardware pointers;
  `park_for_reopen` uses `pcm.delay()`. Null has no comparable buffered tail, so
  the injected tests do not establish sample-accurate cursor recovery for this
  case. Investigate this before claiming complete fallback acceptance.
- Coarse decoder seeking and live device switching were not established as
  sample-accurate/seamless by this run. No GUI visual verification was performed.
- New-head GitHub CI must complete before any merge decision. Main was unchanged
  at `4b63209ce7af23c9c5ca035886d29efe88cd7fff` when last fetched before publication.
